# Context-Scaling Structured Prompt Studio

Interactive demo of the two-stage Context-Scaling pipeline:

```
     natural-language prompt
              │
              ▼   PE model (Qwen3.5-35B-A3B)
     Structured Prompt (JSON)
              │  ← view / edit / drag bboxes in the browser
              ▼   DiT model (QwenImage, fine-tuned on SP)
          rendered image
```

Both models are loaded once at server startup and remain resident in GPU
memory; the browser talks to two FastAPI endpoints (`/api/generate_sp`
and `/api/generate_image`) that call the models in-process.

## Layout

```
demo/
├── app.py                # FastAPI: /api/generate_sp + /api/generate_image + static SPA
├── build_index.py        # Assembles static/index.html from template + css + js
├── Dockerfile            # HF Space image (CUDA 12 + FastAPI + models)
├── requirements.txt      # Runtime deps
├── backend/
│   ├── config.py         # Env-var driven config (checkpoints, devices, defaults)
│   ├── pe.py             # PE model wrapper (transformers, chat template + JSON extract)
│   └── dit.py            # DiT wrapper (reuses training/scripts/serve.py:QwenImagePipeline)
├── static/               # Single-page app (studio-derived template + patched JS)
│   ├── template.html / style.css / script.js
│   └── index.html        # generated by build_index.py
├── system_prompts/
│   ├── rft_iter0_with_ratio_v6_synthesis_student.txt  # default PE system prompt
│   └── qwenimage_official_en.txt                       # alternate NL rewriter
└── test/                 # example structured prompt + reference image
```

## Configuration

All environment-specific values are env vars — see `backend/config.py`
for the full list. The important ones:

| Variable | Default | Meaning |
|---|---|---|
| `PE_CKPT` | `<HDFS_ROOT>/weights/Qwen3.5-35B-A3B` | PE model (local dir or HF Hub repo id) |
| `DIT_CKPT` | `<HDFS_ROOT>/weights/Qwen/Qwen-Image-2512` | DiT root (contains transformer/, vae/, text_encoder/, tokenizer/) |
| `CUDA_VISIBLE_DEVICES` | `0,1` | Physical GPUs the demo may use |
| `PE_DEVICE` | `cuda:1` | Where the PE model lives (after CUDA_VISIBLE_DEVICES remap) |
| `DIT_DEVICE` | `cuda:0` | Where the DiT stack lives |
| `PE_SYSTEM_PROMPT` | `demo/system_prompts/rft_iter0_with_ratio_v6_synthesis_student.txt` | Chat-template system message driving SP synthesis |

## Local run

```bash
# 1. From the OSS repo root.
pip install -r demo/requirements.txt

# 2. (One-off) build the single-file HTML that FastAPI serves.
python demo/build_index.py

# 3. Point the demo at your checkpoints.
export PE_CKPT=/path/to/Qwen3.5-35B-A3B
export DIT_CKPT=/path/to/Qwen-Image-2512
export CUDA_VISIBLE_DEVICES=0,1

# 4. Serve.
python -m demo.app
# or:
uvicorn demo.app:app --host 0.0.0.0 --port 7860
```

Then open http://localhost:7860/.

## Hugging Face Space deployment

This directory is set up as a HF **Docker** Space:

1. Create a new Space with SDK = *Docker*.
2. Push the *contents of the OSS repo root* into the Space repo — the
   Dockerfile at `demo/Dockerfile` is what gets built, but it needs
   `training/` and `demo/system_prompts/` visible at the same repo root.
3. Set `PE_CKPT` and `DIT_CKPT` in the Space's **Variables and secrets**
   panel to point at HF Hub repository ids (or upload the weights and
   use `/data/<name>`).
4. Choose a hardware tier with at least ~80 GB total VRAM across two
   GPUs (the current defaults keep both models resident; sequential
   loading is a future improvement).

The Space YAML in the front-matter of this README is the config HF
picks up automatically.

## Attribution

- The single-page app under `static/` is a *Structured Prompt Studio*
  variant — the two client-side model-call functions
  (`callLLMForSP`, `callDiTForImage`) POST to the local FastAPI backend
  (`/api/generate_sp`, `/api/generate_image`, `/api/caption_image`)
  instead of hitting a remote DiT server directly.
- The DiT pipeline is reused from
  [`training/scripts/serve.py`](../training/scripts/serve.py) with no
  changes; this demo just wraps it in a small in-process adapter.
